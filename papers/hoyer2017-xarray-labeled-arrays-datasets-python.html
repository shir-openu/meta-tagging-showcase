research question — evidence — “Unlabeled, N-dimensional arrays of numbers (e.g., NumPy’s ndarray) are the most widely used data structure in scientific computing. However, they lack a meaningful representation of the metadata associated with their data. Implementing such functionality is left to individual users and domain-specific packages. As a result, programmers frequently encounter pitfalls in the form of questions like “is the time axis of my array in the first or third index position?” or “does my array of timestamps still align with my data after resampling?”.”

mechanismlabel consistency Every operation consumes and preserves labels so data and metadata stay aligned. — “The core motivation for developing xarray was to provide labeled data tools for N-dimensional arrays that render such questions moot. Every operation in xarray both relies on and maintains the consistency of labels.”
mechanismnamed dimensions Dimension names replace positional axes for indexing and aggregation. — “Label-based indexing: Similarly to pandas objects, xarray objects support both integer- and label-based lookups along each dimension. However, xarray objects also have named dimensions, so you can optionally use dimension names instead of relying on the positional ordering of dimensions.”
mechanismcoordinate indexing Ancillary coordinate variables build on pandas Index for fast lookup and alignment. — “xarray uses dims and coords to enable its core metadata-aware operations. Dimensions provide names that xarray uses instead of the axis argument found in many NumPy functions. Coordinates are ancillary variables used to enable fast label based indexing and alignment, building on the functionality of the pandas Index. DataArray objects also can have a name and can hold arbitrary metadata in the form of their attrs property, which can be used to further describe data (e.g. by providing units). Names and attributes are strictly for users and user-written code; in general xarray makes no attempt to interpret them, and propagates them only in unambiguous cases. In contrast, xarray does interpret and persist coordinates in operations that transform xarray objects.”
mechanismdimension-name broadcasting Arithmetic loops over distinct named dimensions without dummy size-one axes. — “Arithmetic: arithmetic between xarray objects vectorizes based on dimension names, automatically looping (broadcasting) over each distinct dimension. This eliminates the need to insert dummy dimensions of size one to facilitate broadcasting, a common pattern with NumPy.”
mechanismcoordinate alignment Database-like joins combine xarray objects along coordinates shared between them. — “Alignment: xarray supports database-like join operations for combining xarray objects along common coordinates.”
mechanismthird-party I/O integration Multiple serialization formats are exposed by integrating their libraries. — “Serialization and I/O: xarray supports direct serialization and I/O to several file formats including pickle, netCDF, OPeNDAP (read-only), GRIB1/2 (read-only), and HDF by integrating with third-party libraries. Additional serialization formats for 1-dimensional data are available through pandas.”
mechanismdask backing Dask-backed structures execute parallel and streaming computations outside memory. — “Out-of-core computation: xarray’s data structures can be backed by dask [21] instead of NumPy to support parallel and streaming computation on data that does not fit into memory, up to 100s of GB or TBs in size. Such large datasets (“big data”) are increasingly prevalent in science.”

(1) Overview

Introduction

Python has emerged as a leading programing language for both the physical sciences and data sciences. At the core of modern scientific computing and analysis in Python are the NumPy [14] and SciPy [22] packages, which provide a robust N-dimensional array object and the fundamental operations required for science and engineering applications. Much of the success of Python in data science and business analytics is due to pandasterm [16], which introduced intuitive and fast tabular data analysis tools to Python, inspired by R’s data.frame [19]. The pandasterm DataFrameterm and Series objects provide unparalleled analysis tools for data alignmentterm, resampling, grouping, pivoting, and aggregation in Python.

xarrayterm implements data structures and an analytics toolkit for multi-dimensional labeled arrays strongly inspired by pandasterm. While pandasterm includes a data structure called the Panelterm for three dimensional data, its fixed rank design make it unsuitable for applications that require arbitrary rank arrays. Additionally, many of the features that make the pandasterm DataFrameterm and Series objects so useful, are not fully available on the Panelterm. Our approach with xarrayterm adopts Unidata’s self-describing Common Data Modelterm on which the network Common Data Formterm (netCDF) is built [20, 7]. NetCDF provides a well-defined data model for labeled N-dimensional array-oriented scientific dataterm analysis.

xarrayterm builds on top of, and seamlessly interoperates with, the core scientific Python packages, such as NumPy, SciPy, Matplotlib [13], and pandasterm. xarrayterm provides a range of backends for serialization and input/output (IO), including the Pickle, netCDF, OPeNDAP (read-only), GRIB1/2 (read-only), and HDF file formats. Leveraging the daskterm parallel computing library [21], xarrayterm can optionally perform efficient parallel, out-of-core analysis on datasets that are too large to fit into memory. Finally, xarrayterm interfaces with existing domain-specific packagesterm such as UV-CDAT [25], Iris [17], and Cartopy [18].

Purpose: Your data has labels; you should use them

Scientific dataterm is inherently labeled. For example, time series data includes timestampsterm·var that label individual periods or points in time, spatial data has coordinatesterm (e.g. longitude, latitude, elevation), and model or laboratory experiments are often identified by unique identifiers. Figure 1 provides an example of a labeled datasetterm. In this case the data is a map of global air temperature from a numeric weather model. Unlabeled, N-dimensional arraysterm of numbers (e.g., NumPy’s ndarray) are the most widely used data structure in scientific computing. However, they lack a meaningful representation of the metadataterm associated with their data. Implementing such functionality is left to individual users and domain-specific packagesterm. As a result, programmers frequently encounter pitfalls in the form of questions like “is the time axis of my array in the first or third index position?” or “does my array of timestampsterm·var still align with my data after resampling?”.

The core motivation for developing xarrayterm was to provide labeled data tools for N-dimensional arrays that render such questions moot. Every operation in xarrayterm both relies on and maintains the consistency of labelsterm.

NetCDF

The network Common Data Formterm is a collection of self-describing, machine-independent binary data formats and software toolsterm. These data formats and tools facilitate the creation, access, and sharing of scientific dataterm stored in N-dimensional arrays, along with metadataterm describing the contents of each array [20]. NetCDF has become very popular in the geoscience community, and there are existing libraries for reading and writing netCDF in many programming languages, including C, Fortran, Python, Java, Matlab, and Julia.

The principal data structure in the netCDF data model is the datasetterm. Each netCDF datasetterm contains dimensions, variables, and attributesterm, each of which are identified by a hierarchy of unique names. The datasetterm and variable objects may contain attributes that describe the contents, units, history, or other metadataterm of the object. Standardized conventions, such as the Climate and Forecast (CF) Conventions [12], allow for the associations of coordinate variables with dimensionsterm.

Implementation and architecture

NetCDF forms the basis of the xarrayterm data model and provides a natural and portable serialization format. Building on netCDF, xarrayterm features two main data structures: the DataArrayterm and the Datasetterm. The API for these data structures is summarized in the following sections and in Figure 2.

DataArrayterm

The DataArrayterm is xarrayterm’s implementation of a labeled, multi-dimensional arrayterm. It has several key properties:

data: N-dimensional array (NumPy or daskterm) holding the array's values,

coords: dict-like containerterm of arrays (coordinatesterm) that label each point (e.g., 1-dimensional arrays of numbers, datetime objects or strings),

dims: dimension namesterm for each axis [e.g., (‘time’, ‘latitude’, ‘longitude’)],

attrsterm·var: OrderedDict holding arbitrary metadataterm (e.g. units or descriptions), and

name: an arbitrary name for the array.

xarrayterm uses dims and coords to enable its core metadata-aware operationsterm. Dimensionsterm provide names that xarrayterm uses instead of the axis argument found in many NumPy functions. Coordinatesterm are ancillary variablesterm used to enable fast label based indexing and alignmentterm, building on the functionality of the pandasterm Index. DataArrayterm objects also can have a name and can hold arbitrary metadataterm in the form of their attrsterm·var property, which can be used to further describe data (e.g. by providing units). Names and attributesterm are strictly for users and user-written code; in general xarrayterm makes no attempt to interpret them, and propagates them only in unambiguous cases. In contrast, xarrayterm does interpret and persist coordinatesterm in operations that transform xarrayterm objects.

Datasetterm

The Datasetterm is xarrayterm’s multi-dimensional equivalent of a DataFrameterm. It is a dict-like containerterm of labeled arrays (DataArrays) with aligned dimensionsterm. It is designed as an in-memory representation of a netCDF datasetterm. In addition to the dict-like interface of the datasetterm itself, which can be used to access any DataArrayterm in a Datasetterm, datasets have four key properties:

data_vars: OrderedDict of DataArrayterm objects corresponding to data variablesterm·var,

coords: OrderedDict of DataArrayterm objects intended to label points used in data_vars (e.g., 1-dimensional arrays of numbers, datetime objects or strings),

dims: dictionary mapping from dimension namesterm to the fixed length of each dimension (e.g., {‘x’: 6, ‘y’: 6, ‘time’: 8}), and

attrsterm·var: OrderedDict to hold arbitrary metadataterm pertaining to the datasetterm.

DataArrayterm objects inside a Datasetterm may have any number of dimensionsterm but are presumed to share a common coordinate system. Coordinatesterm can also have any number of dimensionsterm but denote constant/independent quantities, unlike the varying/dependent quantitiesterm that belong in data. Core xarrayterm Features

xarrayterm includes a powerful and growing feature set. The following list highlights some of the key features available in xarrayterm. The xarrayterm documentation [2] includes a complete description of available features and their usage.

Label-based indexing: Similarly to pandasterm objects, xarrayterm objects support both integer- and label-based lookups along each dimension. However, xarrayterm objects also have named dimensionsterm, so you can optionally use dimension namesterm instead of relying on the positional ordering of dimensionsterm.

Arithmetic: arithmetic between xarrayterm objects vectorizes based on dimension namesterm, automatically looping (broadcasting) over each distinct dimension. This eliminates the need to insert dummy dimensions of size oneterm to facilitate broadcasting, a common pattern with NumPy.

Aggregation: calculation of statistics (e.g. sum) along a dimension of an xarrayterm object can be done by dimension name instead of an integer axis number.

Alignmentterm: xarrayterm supports database-like join operations for combining xarrayterm objects along common coordinatesterm.

Split-apply-combineterm: xarrayterm includes N-dimensional grouped operations implementing the split-apply-combineterm strategy [24].

Resampling and rolling window operations: Utilizing the efficient resampling methods from pandasterm and rolling window operations from Bottleneck [15], xarrayterm offers a robust set of resampling and rolling window operations along a single dimension.

Plotting: xarray plotting functionalityterm is a thin wrapperterm around the popular Matplotlib library. xarrayterm uses the syntax and function names from Matplotlib whenever possible, resulting in a seamless transition between the two.

Missing Dataterm: xarrayterm smoothly handles missing dataterm in all operations, including arithmetic, alignmentterm and aggregation.

Interactivity with pandasterm: xarrayterm objects seamlessly to convert to and from pandasterm objects to interact with the rest of the PyData ecosystem.

Serialization and I/Oterm: xarrayterm supports direct serialization and I/Oterm to several file formats including pickle, netCDF, OPeNDAP (read-only), GRIB1/2 (read-only), and HDF by integrating with third-party librariesterm. Additional serialization formats for 1-dimensional data are available through pandasterm.

Out-of-core computationterm: xarrayterm’s data structures can be backed by daskterm [21] instead of NumPy to support parallel and streaming computationterm on data that does not fit into memory, up to 100s of GB or TBs in size. Such large datasets (“big data”) are increasingly prevalent in science.

(3) Reuse potential

xarrayterm was written in a modular, objected-oriented way, to build upon and extend the core scientific Python librariesterm in a domain-agnostic fashion. The xarrayterm documentation is complete with a wide range of examples and a number of tutorials that use real-world datasets that are available in the xarrayterm repository. We have intentionally avoided including domain-specific functionalityterm in the library, leaving that to third party libraries. It has been widely adopted in the geoscience community [e.g. 6, 10, 9], but has also been used in physics [e.g. 3], time series analytics [8], and finance. The core xarrayterm data structures (the DataArrayterm and the Datasetterm) are extensible through subclassing or the preferred approach of compositionterm. We also provide an extensible high-level accessor interfaceterm to allow users to implement domain specific methods on xarrayterm data objects.

xarrayterm is developed and supported by a team of volunteersterm. The primary avenue for user support is StackOverflow [4], with the “xarray-python” tag.
