Background

Simple integrated analysis work flows for single-cell transcriptomic data [ 1 ] have been enabled by frameworks such as SEURATterm·dom [ 2 ], MONOCLE [ 3 ], SCDE/PAGODA [ 4 ], MAST [ 5 ], CELL RANGERterm·dom [ 6 ], SCATER [ 7 ], and SCRAN [ 8 ]. However, these frameworks do not scale to the increasingly available large data sets with up to and more than one million cells. Here, we present a framework that overcomes this limitation and provides similar analysis possibilities. Moreover, in contrast to the existing R-based frameworks, SCANPYterm·dom ’s Python-based implementation is easy to interface with advanced machine-learning packages, such as TENSORFLOW [ 9 ].

Results

SCANPYterm·dom integrates canonical analysis methods in a scalable way

SCANPYterm·dom integrates the analysis possibilities of established R-based frameworks and provides them in a scalable and modular form. Specifically, SCANPYterm·dom provides preprocessingterm comparable to SEURATterm·dom [ 10 ] and CELL RANGERterm·dom [ 6 ], visualizationterm through TSNE [ 11 , 12 ], graph-drawing [ 13 – 15 ] and diffusion maps [ 11 , 16 , 17 ], clusteringterm similar to PHENOGRAPH [ 18 – 20 ], identification of marker genes for clusters via differential expression tests and pseudotemporal ordering via diffusion pseudotime [ 21 ], which compares favorably [ 22 ] with MONOCLE 2 [ 22 ], and WISHBONE [ 23 ] (Fig. 1 a).

SCANPYterm·dom is benchmarked in comparisons with established packages

In a detailed clusteringterm tutorial of 2700 peripheral blood mononuclear cells (PBMCs), adapted from one of SEURATterm·dom ’s tutorials ( http://satijalab.org/seuratterm·dom/pbmc3k_tutorial.html ) [ 2 ], all steps starting from raw count data to the identification of cell types are carried out, providing speedups between 5 and 90 times in each step ( https://github.com/theislab/scanpyterm·dom_usage/tree/master/170505_seuratterm·dom ). Benchmarking against the more run-time optimized CELL RANGERterm·dom R kit [ 6 ], we demonstrate a speedup of 5 to 16 times for a data set of 68,579 PBMCs (Fig. 1 a,b, https://github.com/theislab/scanpyterm·dom_usage/tree/master/170503_zheng17 ) [ 6 ]. Moreover, we demonstrate the feasibility of analyzing 1.3 million cells without subsampling in a few hours of computing time on eight cores of a small computing server (Fig. 1 c, https://github.com/theislab/scanpyterm·dom_usage/tree/master/170522_visualizing_one_million_cells ). Thus, SCANPYterm·dom provides tools with speedups that enable an analysis of data sets with more than one million cells and an interactive analysis with run times of the order of seconds for about 100,000 cells.

In addition to the mentioned standard clustering-based analyses approaches, we demonstrate the reconstruction of branching developmental processes via diffusion pseudotime [ 21 ] as in the original paper ( https://github.com/theislab/scanpyterm·dom_usage/tree/master/170502_haghverdi16 ), the simulation of single cells using literature-curated gene regulatory networks based on the ideas of [ 24 ] ( https://github.com/theislab/scanpyterm·dom_usage/tree/master/170430_krumsiek11 ), and the analysis of deep-learning results for single-cell imaging data [ 25 ] ( https://github.com/theislab/scanpyterm·dom_usage/tree/master/170529_images ).

SCANPYterm·dom introduces efficient modular implementation choices

With SCANPYterm·dom , we introduce the class ANNDATAterm·dom —with a corresponding package ANNDATAterm·dom —which stores a data matrixterm·dom with the most general annotationsterm·dom possible: annotationsterm·dom of observations (samples, cells) and variables (features, genes), and unstructured annotationsterm·dom. As SCANPYterm·dom is built around that class, it is easy to add new functionality to the toolkit. All statistics and machine-learning tools extract information from a data matrixterm·dom, which can be added to an ANNDATAterm·dom object while leaving the structure of ANNDATAterm·dom unaffected. ANNDATAterm·dom is similar to R’s EXPRESSIONSETterm·dom [ 26 ], but supports sparse dataterm·dom and allows HDF5-based backingterm of ANNDATAterm·dom objects on disk, a format independent of platform, framework, and language. This allows operating on an ANNDATAterm·dom object without fully loading it into memory—the functionality is offered via ANNDATAterm·dom ’s backed modeterm·dom as opposed to its memory modeterm·dom. To simplify memory-efficient pipelines, SCANPYterm·dom ’s functions operate in-placeterm by default but allow the optional non-destructive transformationterm of objects. Pipelines written this way can then also be run in backed modeterm·dom to exploit online-learning formulationsterm of algorithms. Almost all of SCANPYterm·dom ’s tools are parallelized.

SCANPYterm·dom introduces a class for representing a graph of neighborhood relationsterm among data points. The computation of neighborhood relationsterm·dom is much faster than in the popular reference package [ 27 ]. This is achieved by aggregating rows (observations) in a data matrixterm·dom to submatrices and computing distances for each submatrix using fast parallelized matrix multiplication. Moreover, the class provides several functions to compute random-walk-based metricsterm that are not available in other graph software [ 14 , 28 , 29 ]. Typically, SCANPYterm·dom ’s tools reuse a once-computed, single graph representationterm·dom of data and hence, avoid the use of different, potentially inconsistent, and computationally expensive representations of data.

Conclusions

SCANPYterm·dom ’s scalability directly addresses the strongly increasing need for aggregating larger and larger data sets [ 30 ] across different experimental setups, for example within challenges such as the Human Cell Atlas [ 31 ]. Moreover, being implemented in a highly modular fashion, SCANPYterm·dom can be easily developed further and maintained by a community. The transfer of the results obtained with different tools used within the community is simple, as SCANPYterm·dom ’s data storage formats and objects are language independent and cross-platform. SCANPYterm·dom integrates well into the existing Python ecosystemterm·dom, in which no comparable toolkit yet exists.

During the revision of this article, the loom file format ( https://github.com/linnarsson-lab/loompy ) was proposed for HDF5-based storage of annotated data. Within a joint effort of facilitating data exchange across different labs, ANNDATAterm·dom now supports importing and exporting to loom ( https://github.com/linnarsson-lab/loompy ). In this context, we acknowledge the discussions with S. Linnarson, which motivated us to extend ANNDATAterm·dom ’s previously staticterm·dom to a dynamic HDF5 backingterm·dom. Just before submission of this manuscript, a C++ library that provides simple interfacing of HDF5-backed matrices in R was made available as a preprint [ 32 ].

Methods

SCANPYterm·dom ’s technological foundations

SCANPYterm·dom ’s core relies on NUMPY [ 33 ], SCIPY [ 34 ], MATPLOTLIB [ 35 ], PANDAS [ 36 ], and H5PY [ 37 ]. Parts of the toolkit rely on SCIKIT-LEARN [ 27 ], STATSMODELS [ 38 ], SEABORN [ 39 ], NETWORKX [ 28 ], IGRAPH [ 14 ], the TSNE package of [ 40 ], and the Louvain clusteringterm package of [ 41 ]. The ANNDATAterm·dom class—available within the package ANNDATAterm·dom —relies only on NUMPY , SCIPY , PANDAS , and H5PY .

SCANPYterm·dom ’s Python-based implementation allows easy interfacing to advanced machine-learning packages such as TENSORFLOW [ 9 ] for deep learning [ 42 ], LIMIX for linear mixed models [ 43 ], and GPY/GPFLOW for Gaussian processes [ 44 , 45 ]. However, we note that the Python ecosystemterm·dom comes with less possibilities for classical statistical analyses compared to R.

Comparison with existing Python packages for single-cell analysis

Aside from the highly popular SCLVM ( https://github.com/PMBio/scLVM ) [ 46 , 47 ], which uses Gaussian process latent variable models for inferring hidden sources of variation, there are, among others, the visualizationterm frameworks FASTPROJECT ( https://github.com/YosefLab/FastProject ) [ 48 ], ACCENSE ( http://www.cellaccense.com/ ) [ 49 ], and SPRING ( https://github.com/AllonKleinLab/SPRING ) [ 15 ]—the latter uses the JavaScript package ( http://d3js.org D3.js for the actual visualizationterm and Python only for preprocessingterm—the trajectory inference tool SCIMITAR ( https://github.com/dimenwarper/scimitar ), the clusteringterm tool PHENOGRAPH ( https://github.com/jacoblevine/PhenoGraph ) [ 19 ], the single-cell experiment design tool MIMOSCA ( https://github.com/asncd/MIMOSCA )[ 50 ], UMIS ( https://github.com/vals/umis ) for handling raw read data [ 51 ], the tree-inference tool ECLAIR ( https://github.com/GGiecold/ECLAIR ) [ 52 ], and the framework FLOTILLAterm ( https://github.com/yeolab/flotillaterm ), which comes with modules for simple visualizationterm, simple clusteringterm, and differential expression testingterm. Hence, only the latter provides a data analysis frameworkterm that solves more than one specific task. In contrast to SCANPYterm·dom , however, FLOTILLAterm is neither targeted at single-cell nor at large-scale dataterm and does not provide any graph-based methodsterm, which are the core of SCANPYterm·dom . Also, FLOTILLAterm is built around a complicated class STUDYterm·dom , which contains data, tools, and plotting functions. SCANPYterm·dom , by contrast, is built around a simple HDF5-backed class ANNDATAterm·dom , which makes SCANPYterm·dom both scalable and extendable (law of Demeter).
