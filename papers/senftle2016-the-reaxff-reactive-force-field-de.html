mechanismone type, two branches ReaxFF's defining choice is that an element has ONE description regardless of environment, which is what lets an atom migrate between phases mid-simulation. The cost is that a parameter set cannot be specialised without changing the shared atom-level parameters - so the specialisation became a BRANCH instead of a TYPE. mechanismthe scope decision that became a failure liquid water was not a development aim for the 2008 combustion field because every intended application was above the boiling point. mechanisma fork that cannot be undone cheaply parameter sets on the same branch combine by fitting only the bond and angular terms between the newly combined elements; across branches it takes extensive refitting, and combustion-to-aqueous is the easier direction. THE ASYMMETRY IS A FACT ABOUT THE FITTING HISTORY, not about the chemistry— “Parameter sets on the same development branch can be directly combined, where the required force-field fitting consists only of parameterising bond and angular terms between the newly combined elements. Transferring parameters between branches, however, requires more extensive refitting.”
mechanismbranches merge by refitting, not by agreement several independent branches - B/N/H, Ni/C/H - began as non-transferable descriptions and were later merged into combustion or aqueous through extensive refitting. A vocabulary reconciled by redoing the work rather than by declaring the terms equivalent— “Typically these sets began as non-transferable ReaxFF descriptions constituting independent development branches, but many have later been merged, through extensive refitting, with the combustion (C/B/N/H/O)34 or aqueous branches (Ni/C/H/O).”
